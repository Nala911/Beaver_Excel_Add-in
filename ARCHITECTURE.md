# Beaver Add-in: System Architecture & Module Map

This document outlines the architectural layers and dependencies of the Beaver Excel Add-in. It is automatically generated by the build pipeline to guide human developers and AI coding agents.

## Architectural Health & Layer Integrity

> [!NOTE]
> **Architectural Health: 100% Compliant**. No upward layer violations detected in production code!

## Architectural Layering Rules

The codebase is organized into five strict horizontal layers. To prevent spaghetti code and circular dependency loops, dependencies must only flow **downward** (i.e. high-level layers can call lower-level layers, but never vice versa).

| Layer | Prefix / Folder | Role & Responsibility | Permitted Dependencies |
| :--- | :--- | :--- | :--- |
| **UI** | UI_ / Modules/UI | Ribbon interface definitions, event handlers, and UserForms. | Feature, Infrastructure, Library, Core |
| **Feature** | FeatCmd_ / Modules/Commands | Individual business commands implementing ICommand. | Infrastructure, Library, Core |
| **Infrastructure** | Infra_ / Modules/Infrastructure | Cross-cutting systems (Undo registry, Hotkeys, Configuration, Diagnostics, Error context). | Library, Core |
| **Library** | Lib_ or Udf_ / Modules/Libraries | Pure helper functions, utilities, and User Defined Functions (UDFs). | Core |
| **Core** | /Modules/Core | Base interfaces (ICommand, ICommandContext), central contexts (ActionContext), and enums. | *None (Completely decoupled)* |

> [!IMPORTANT]
> **Dependency Direction**: Higher-level layers (UI, Features) may depend on lower-level layers (Infrastructure, Libraries, Core), but lower-level layers must **never** depend on higher-level layers. Circular dependencies are strictly prohibited.

## Core Design Patterns

### 1. The Command Pattern (`ICommand`)
All workbook features are implemented as class modules conforming to the `ICommand` interface:
1. **Trigger**: An entry point in `UI_Ribbon` or `UI_Hotkeys` captures user interaction.
2. **Context**: An `ActionContext` (implementing `ICommandContext`) is initialized to store target ranges, parameters, and application state.
3. **Execution**: The command is dispatched to `CommandInvoker.Execute`, which validates the context, logs telemetry, tracks history for Undo, and calls the command's custom `ICommand_Execute` method.

### 2. State & Safety Management (`Infra_AppState`)
To ensure fast execution and a clean user experience, Excel screen updating, events, and automatic calculation must be disabled during heavy operations.
* Always wrap operations in an `Infra_AppStateGuard` context or manually handle it using:
  ```vba
  Dim appState As Infra_AppState: Set appState = Infra_AppState.DisableSpeedSettings()
  On Error GoTo ErrHandler
  ' ... work ...
  appState.Restore
  ```

## AI Agent Development Conventions
AI coding agents editing this repository must adhere to the following rules:
* **Option Explicit**: Every source file must contain `Option Explicit` as its first line.
* **Metadata Headers**: Every file must start with `@Module`, `@Category`, `@Description`, and `@Dependencies` comments.
* **Context & Errors**: Every public procedure must use `Infra_Error.Track` and standard `ErrHandler` error traps.
* **Excel References**: Always qualify ranges with sheet variables (e.g. `ws.Range` instead of `Range`). Never call conversion functions directly on range properties without checking for `Null` first.
