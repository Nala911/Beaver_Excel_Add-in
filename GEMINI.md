# Beaver Add-in - Gemini Context

Read this before changing VBA, Ribbon metadata, manifests, or workbook sync behavior.

Last updated: 2026-04-30
Current config version: 2.0.68

## Purpose

Beaver is an Excel VBA add-in for fast workbook operations and lightweight automation inside Excel. Its feature surface currently includes:

- range formatting and paste-format helpers
- formula manipulation and formula-to-value conversion
- text cleanup and date normalization
- workbook duplication and range export
- link breaking and worksheet workspace toggles
- a manifest-driven Ribbon and hotkey system
- worksheet UDFs: `XFilter` and `XUnpivot`
- a lightweight VBA test harness
- a command-oriented execution pipeline built around `ICommand`

## Source Of Truth

Treat the exported text files in this repo as authoritative:

- `Modules\*.bas` and `Modules\*.cls` are the editable VBA source.
- `ThisWorkbook.cls` is the authoritative workbook event module on disk.
- `features.json` is the authoritative feature manifest for Ribbon controls, command names, icons, release tiers, runtime-test modes, and hotkeys.
- `config.json` is the authoritative configuration for add-in identity and UI constants. `Update.ps1` synchronizes its `Hotkeys`, `Icons`, and `FeatureFlags` sections from `features.json`.
- `ribbon.xml` is generated from `features.json` by `Update.ps1`.
- `Beaver Add-in.xlsm` is the compiled workbook artifact synchronized by `Update.ps1`.

Do not make manual changes in the VBE and leave disk exports stale. Edit text files first, then run `.\Update.ps1`.

## Do Not Touch

- `Beaver Add-in.xlsm` directly. Always use `Update.ps1`.
- `Modules\Lib_JsonConverter.bas`. It is a third-party library.
- `Update.ps1` unless the build pipeline itself is the task.
- `.frx` files. They are binary and auto-generated by the VBE.
- hidden workbook support sheets such as `_BeaverUndo` or `_BeaverTests`, if they exist.

## Runtime Architecture

The current architecture is command-oriented rather than direct macro-to-feature wiring.

### Entry Paths

1. Workbook lifecycle:
   `ThisWorkbook.Workbook_Open` calls `Infra_Bootstrap.Startup`.
   `ThisWorkbook.Workbook_BeforeClose` calls `Infra_Bootstrap.Shutdown`.

2. Ribbon callbacks:
   `UI_Ribbon.bas` exposes `Ribbon_On*` procedures referenced by `features.json` and `ribbon.xml`.
   These callbacks do not perform heavy business logic directly. They call `AppContainer.ExecuteEntryPoint`.

3. Hotkeys:
   `Infra_Hotkeys` registers `Application.OnKey` bindings from `config.json`.
   Those bindings point to `UI_Hotkeys.bas`, and `UI_Hotkeys` forwards to `AppContainer.ExecuteEntryPoint`.

### Bootstrap And Container

- `Infra_Bootstrap.Startup` initializes `AppContainer` with `Infra_Config`, `Infra_Error`, and `StateStore`, then registers hotkeys.
- `Infra_Bootstrap.Shutdown` unregisters hotkeys.
- `Infra_Bootstrap.EnsureStarted` ensures container initialization for late entry scenarios.
- `AppContainer` is the central dependency container and command resolver.
- `AppContainer.ResolveCommand` maps manifest command names such as `MergeFormulas` or `Dashboard` to `FeatCmd_*` classes.
- `AppContainer.CreateCommandContext` builds a `BasicCommandContext` with entry macro, source, trigger kind, and captured Excel action context.

### Command Pipeline

- `features.json` and hotkey metadata define `CommandName` values.
- `Infra_CommandCatalog` reads `features.json` and maps entry macros to command names.
- `AppContainer.ExecuteEntryPoint` resolves the command name from the callback macro and creates the command object.
- `CommandInvoker.ExecuteCommand` runs `CanExecute`, applies `Infra_AppStateGuard`, and then calls `Execute`.
- Shared helpers in `Infra_CommandSupport` convert `ICommandContext` into `Infra_ActionContext`.

### Shared Infrastructure

- `Infra_AppStateGuard` captures and restores Excel application state such as `ScreenUpdating`, `EnableEvents`, `DisplayAlerts`, and `Calculation`.
- `Infra_AppState` captures workbook, worksheet, cell, and range context and provides selection helpers.
- `Infra_Config` loads `config.json` through the typed `Infra_ConfigModel`.
- `Infra_Error` centralizes tracking, breadcrumbs, diagnostics, user-facing error handling, and failsafe reset behavior.
- `Infra_ContextTracker` provides RAII-style `PushContext` and `PopContext` support via `Infra_Error.Track`.
- `Infra_Undo` provides custom undo support for macro-driven changes.
- `Infra_Progress` provides status-bar progress reporting.
- `Infra_Diagnostics` and `Infra_ErrorContext` support environment capture and troubleshooting.
- `StateStore` and `AppContainer` provide shared process-level state and dependency access.

## VBA Rules

- `Option Explicit` is mandatory in every `.bas` and `.cls` file.
- Every VBA source file should include the metadata header:

```vba
' @Module: ModuleName
' @Category: Infrastructure/Feature/UI/Library
' @Description: Short description
' @ManagedBy: BeaverAddin Agent
' @Dependencies: Dependency list
```

- Keep UI callbacks and workbook events thin.
- Prefer command classes (`FeatCmd_*`) for new feature work.
- If implementing `ICommand`, include both `CanExecute` and `Execute`.
- Use `Infra_CommandSupport.ActionContextFromCommandContext` or captured `Infra_ActionContext` instead of re-reading globals repeatedly.
- Prefer array-based range processing over cell-by-cell loops for bulk edits.
- Use `.Formula2` for modern formulas and spill-safe behavior.
- Preserve user-facing constants in `config.json`.
- Do not manually edit generated test manifests or generated Ribbon output unless the task specifically targets the generator/build path.

## Error Handling Pattern

Public entry points, UI callbacks, and lifecycle hooks should follow the centralized error pattern:

```vba
Public Sub MyMacro()
    Dim tracker As Object: Set tracker = Infra_Error.Track("MyMacro")
    Dim guard As New Infra_AppStateGuard
    On Error GoTo ErrHandler

    ' work

CleanExit:
    Exit Sub

ErrHandler:
    Infra_Error.HandleError "MyMacro", Err
    Resume CleanExit
End Sub
```

Rules:

- Use `Infra_Error.Track` at the start of every public macro, Ribbon callback, hotkey wrapper, and workbook event.
- Use `Infra_AppStateGuard` for code that changes Excel application state.
- Use `Infra_Undo.SaveState` before mutating ranges when custom undo should be preserved.
- Use `Infra_Progress` for operations that may take noticeable time.
- Prefer a single `CleanExit` label when there are early returns.
- Route failures through `Infra_Error.HandleError` instead of ad hoc dialogs.

## Manifest And UI Rules

- Prefer editing `features.json` over hand-editing `ribbon.xml`.
- Keep `features.json`, `config.json`, `ribbon.xml`, `UI_Ribbon.bas`, `UI_Hotkeys.bas`, `Infra_CommandCatalog`, and `AppContainer.ResolveCommand` aligned.
- A new Ribbon feature usually needs:
  - a `Features` entry in `features.json`
  - a matching `Ribbon_On*` callback in `UI_Ribbon.bas`
  - a `CommandName`
  - a `FeatCmd_*` implementation
  - a resolver case in `AppContainer.ResolveCommand`
  - an icon entry synced into `config.json`
- A new hotkey usually needs:
  - a `Hotkeys` entry in `features.json`
  - a wrapper in `UI_Hotkeys.bas`
  - a `CommandName`
  - a command class or mapped existing command
- If a feature can run unattended, set `"RuntimeTestMode": "headless"` in `features.json`.
- Interactive features should remain marked `"interactive"` so runtime smoke tests know their behavior.

## Build And Sync Workflow

Standard workflow:

1. Edit source files on disk.
2. Run `.\Update.ps1`.
3. Fix validation, import, compile, Ribbon, or runtime-test failures.

Useful commands:

```powershell
.\Update.ps1
.\Update.ps1 -BumpVersion
.\Update.ps1 -IncludeDevFeatures
.\Update.ps1 -SkipRuntimeTests
```

`Update.ps1` currently:

- validates Ribbon XML
- synchronizes `features.json` into `ribbon.xml`
- synchronizes `Hotkeys`, `Icons`, and `FeatureFlags` into `config.json`
- generates `Modules\Lib_TestManifest.bas` from `Public Sub Test_*`
- verifies Ribbon callbacks exist in exported VBA
- enforces structure checks, `Option Explicit`, and metadata headers
- closes the workbook if Excel has it locked
- reimports managed VBA components from disk
- replaces `ThisWorkbook` from `ThisWorkbook.cls`
- compiles the VBA project through Excel/VBE automation
- saves the workbook
- injects `ribbon.xml` into the `.xlsm` archive as `customUI/customUI14.xml`
- runs runtime smoke tests unless `-SkipRuntimeTests` is used
- bumps the patch/build version when `-BumpVersion` is passed

Prerequisites:

- Excel must allow trust access to the VBA project object model.
- The environment must support Excel COM automation.

## Current Development Directions

When making future changes, prefer these directions:

- extend the command architecture instead of adding direct feature logic to Ribbon or hotkey wrappers
- keep workbook events thin and route startup work through `Infra_Bootstrap`
- treat manifest metadata as the driver for UI, command routing, and test behavior
- consolidate reusable state, diagnostics, and config access in infrastructure modules instead of feature duplication
- keep new features compatible with runtime validation by choosing the right `RuntimeTestMode`

## Checklist

- Read the target module and its `@Dependencies` first.
- If touching Ribbon behavior, verify callback names and manifest entries match.
- If adding a command, update both `AppContainer.ResolveCommand` and the manifest-driven entry mapping path.
- If adding a config value, update both `Infra_ConfigModel` and `Infra_Config`.
- If mutating a range, consider `Infra_Undo.SaveState`.
- If the task is slow, add `Infra_Progress`.
- Run `.\Update.ps1` after meaningful changes.

## Known Gotchas

- Use `.Formula2`, not `.Formula`, for dynamic arrays and spill-safe formulas.
- `ThisWorkbook` now routes through `Infra_Bootstrap`, not directly to `Infra_Hotkeys`.
- `config.json` version values may be updated by `Update.ps1`; do not hand-manage patch increments.
- Ribbon XML changes require workbook reload or Excel restart to be reflected.
- `Infra_CommandCatalog` reads `features.json` at runtime and also has fallback mappings; keeping both manifest and command resolver aligned avoids drift.
- `Infra_AppStateGuard` should be declared inline as `Dim guard As New Infra_AppStateGuard` so cleanup runs on scope exit.
- `Infra_Error.Track` should be assigned to an object variable so RAII cleanup occurs correctly.
